# audit-case-explorer 개발 로드맵

계정과목을 시작점으로 금융감독원 감리지적사례를 3클릭 안에 찾아내는 내부 지식 웹앱을 만든다.

> ⚠️ **이 문서는 Next.js 앱 트랙(`audit-case-explorer`) 전용입니다.**
> 이 저장소는 두 개의 독립된 작업 트랙(`CLAUDE.md` 참고)을 담고 있습니다. 본 로드맵은 `src/` 아래 Next.js 웹앱만 다루며, `data/audit-cases/` 의 **감리지적사례 지식 추출 파이프라인 트랙**(PDF → 사례 카드 생성·검증)과는 작업 범위·산출물·담당자가 모두 다릅니다. 파이프라인 트랙의 진행 상황은 `data/audit-cases/knowledge/sourcebook-index.md`, `taxonomy.md`, `verification-report.md`를 직접 참고하세요. 두 트랙을 이 문서 안에서 섞지 않습니다.
> 본 로드맵에서 `data/audit-cases/knowledge/cases/`는 **읽기 전용 입력 데이터**로만 취급합니다. 앱 트랙 작업 중 사례 카드 원본을 수정하지 않습니다.

## 개요

### 구현 매체에 대한 결정 (PRD와 다른 방향)

`docs/PRD.md`는 "감리지적사례 조회 시스템"을 **순수 Notion 워크스페이스**로 구현하는 것을 전제로 작성된 문서이며, §11(범위 외)에서 "별도 웹/모바일 앱 개발"을 MVP 제외 범위로 명시하고 있습니다. **본 로드맵은 이 지점에서 의도적으로 PRD와 다른 방향을 취합니다.**

- **근거**: 사용자가 이 저장소를 실제 구현체로 결정했습니다. `README.md`는 이 저장소를 "계정과목별 금융감독원 감리지적사례를 조회하는 내부 지식 시스템의 Next.js 프론트엔드"로 정의하고 있고, `package.json`의 `name`은 `audit-case-explorer`입니다.
- **따라서 PRD의 위상**: PRD는 이제 **요구사항(F-01~F-10)·데이터 모델·KPI의 원천 문서**로만 인용합니다. 구현 매체에 관한 PRD의 서술(Notion DB/뷰/칸반 등)은 본 로드맵에 구속력이 없습니다.
- **감추지 않는 사실**: PRD §11과 충돌하므로, PRD를 갱신하거나 "구현 매체 변경" 결정 로그를 PRD에 추가하는 작업이 별도로 필요합니다(→ 미결정 사항 참조).
- **데이터 원천**: Notion API를 사용하지 않습니다. `data/audit-cases/knowledge/cases/`의 **로컬 마크다운 62개 파일**을 빌드타임에 파싱합니다(`@notionhq/client` 미도입, `package.json`에도 없음).

### 제품 정의

`audit-case-explorer`는 회계법인·기업 재무팀의 실무 감사인을 위한 **계정과목 기반 감리지적사례 탐색 도구**로 다음 기능을 제공합니다:

- **계정과목별 사례 탐색**: 계정과목을 클릭하면 해당 과목에 연결된 감리지적사례 목록으로 진입 (N:M 관계)
- **사례 상세 열람**: 요약 → 지적유형·조치수준 → 관련 계정과목 → 근거 문장 → 원문 출처의 고정 순서로 사례를 읽는 표준 템플릿
- **지적유형·연도·검수상태 필터**: 6종 지적유형 분류체계 기반 교차 필터와 URL 쿼리 동기화
- **데이터 신뢰도 가시화**: 원문 대조 검증 완료 여부·검수상태를 화면에 정직하게 노출 (초안 데이터를 검증된 데이터처럼 보이게 하지 않음)

### 데이터 현황 및 이 로드맵이 반드시 해결해야 할 제약 3가지

현재 `data/audit-cases/knowledge/`의 실제 상태에서 파생되는 **설계 제약**입니다. 이 세 가지를 무시하면 화면이 비거나 인덱스가 깨집니다.

| #   | 제약                                              | 실제 데이터 상태                                                                                                                          | 대응 Task                                                                |
| --- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 1   | **검수상태 전량 "초안"**                          | 62/62건이 `검수상태: 초안`. PRD F-05의 "공개 상태만 노출" 게이트를 곧이곧대로 적용하면 화면에 아무것도 뜨지 않음                          | Task 002(플래그 정의) · Task 007(게이트 연동) · Task 009(뱃지·경고 배너) |
| 2   | **조치수준 전량 "[확인필요]"**                    | 62/62건이 `조치수준: [확인필요]`. 원문 PDF에 해당 필드 자체가 없어 추출 불가                                                              | Task 004(전용 렌더링) · Task 007(정렬/필터 축에서 제외)                  |
| 3   | **관련계정과목이 자유 텍스트** ⚠️ **최대 리스크** | `매출액(연결)`, `금융자산(FVOCI/FVPL/AC 분류)` 등 표기가 제각각. 그대로 쓰면 계정과목별 N:M 인덱스가 파편화되어 제품의 핵심 진입점이 붕괴 | **Task 006(정규화 사전 구축 — 별도 Task로 분리)**                        |

추가 사실:

- **지적유형 6종 확정**(`taxonomy.md`): 자산평가 20건 · 수익인식 17건 · 부정관련 자산 허위계상 9건 · 부채인식 8건 · 공시누락 5건 · 연결범위·연결처리 오류 4건 (합 62)
- **원문 대조 검증 17/62건(27%)만 완료**(`verification-report.md`), 불일치 2건 · 부분일치 3건 미해소 → 앱에서 이 상태를 감추지 않고 표시
- **원문 PDF는 `raw/`에 151쪽 1개 파일**, 62건 전부가 그 안에 있음. 카드 출처 표기 형식은 `인쇄쪽 N~M (PDF쪽 N+6~M+6)` → 딥링크 시 **+6 오프셋 변환 규칙** 필요

### 기술 스택 (기존 저장소 상태 준수)

- Next.js 15.5.3 (App Router + Turbopack) / React 19.1.0 / TypeScript 5 strict (`any` 금지)
- TailwindCSS v4 + shadcn/ui (`new-york`, base color `neutral`) — `src/components/ui/`에 프리미티브 18종 기존재
- React Hook Form + Zod / `next-themes` 다크모드 / ESLint + Prettier + Husky + lint-staged
- **재사용 원칙**: `src/components/ui/`(badge, card, separator, skeleton 등), `src/components/layout/`(header, footer, container), `src/components/navigation/`(main-nav, mobile-nav), `src/components/providers/`(theme-provider)는 **전부 재사용 대상이며 신규 프리미티브 추가를 금지**합니다. 필요한 것은 도메인 컴포넌트이지 프리미티브가 아닙니다.
- **테스트 러너 미구성** — Jest/Vitest 없음. 본 로드맵의 기능 검증은 **Playwright MCP를 통한 브라우저 E2E 확인**으로 수행합니다.

## 개발 워크플로우

1. **작업 계획**

- 기존 코드베이스를 학습하고 현재 상태를 파악
- 새로운 작업을 포함하도록 `docs/ROADMAP.md` 업데이트
- 우선순위 작업은 마지막 완료된 작업 다음에 삽입

2. **작업 생성**

- 기존 코드베이스를 학습하고 현재 상태를 파악
- `/tasks` 디렉토리에 새 작업 파일 생성 (현재 미생성 — Task 001 착수 시 함께 생성)
- 명명 형식: `XXX-description.md` (예: `001-app-skeleton.md`)
- 고수준 명세서, 관련 파일, 수락 기준, 구현 단계 포함
- **API/비즈니스 로직 작업(Task 005~009)은 "## 테스트 체크리스트" 섹션 필수 포함 (Playwright MCP 테스트 시나리오 작성)**
- 예시를 위해 `/tasks` 디렉토리의 마지막 완료된 작업 참조. 예를 들어 현재 작업이 `007`이라면 `006`과 `005`를 예시로 참조
- 완료된 작업 파일은 최종 상태(체크된 박스 + 변경 사항 요약)를 반영하므로, 새 작업 문서는 빈 박스에 변경 사항 요약 없이 시작. 초기 상태 샘플은 `000-sample.md` 참조

3. **작업 구현**

- 작업 파일의 명세서를 따름
- 기능과 기능성 구현
- **콘텐츠 파이프라인·검색·필터 등 비즈니스 로직 구현 시 Playwright MCP로 테스트 수행 필수**
- 각 단계 후 작업 파일 내 단계 진행 상황 업데이트
- 구현 완료 후 `npm run check-all` + `npm run build` 통과 확인, 이어서 Playwright MCP E2E 확인
- 테스트 통과 확인 후 다음 단계로 진행
- 각 단계 완료 후 중단하고 추가 지시를 기다림

4. **로드맵 업데이트**

- `/update-roadmap` 커맨드로 완료된 작업을 ✅로 표시하고 하단 진행 상황 두 줄을 갱신
