## 2. 배경 및 문제 정의

회계사는 감사 절차 중 특정 계정과목(예: 매출채권, 재고자산)에서 유의한 위험을 식별하면, 유사한 금융감독원 감리지적사례를 참고해 감사 접근법을 보강한다. 현재는 이 참고 과정이 다음과 같이 비효율적이다.

- 감리지적사례집 PDF(수백 페이지)를 사람이 직접 검색·스크롤하며 관련 사례를 찾음
- 계정과목과 사례 간의 매핑이 개인의 기억과 경험에 의존 — 팀 내 지식이 공유되지 않음
- 동일 사례를 여러 감사팀원이 각자 다시 찾는 중복 작업 발생

## 3. 목표 및 성공지표

| 목표                               | 성공지표 (KPI)                                         |
| ---------------------------------- | ------------------------------------------------------ |
| 계정과목에서 관련 사례로 즉시 도달 | 계정과목 클릭 → 관련 사례 목록 도달까지 **3클릭 이내** |
| 신뢰할 수 있는 요약 제공           | 공개 상태 사례의 **100%가 회계사 검수 완료** 상태      |
| 초기 지식베이스 구축               | MVP 종료 시점 **감리지적사례 30~50건** 등록 및 매핑    |
| 팀 내 지식 재사용                  | 워크스페이스 내 감사팀원 접근 가능 비율 100%           |

## 5. 핵심 사용자 시나리오

**주 흐름 — 계정과목 클릭 → 사례 열람 → PDF 다운로드**

1. 회계사가 배정된 회사 페이지에서 계정과목(예: `매출채권`)을 클릭한다.
2. 해당 계정과목에 Relation으로 연결된 감리지적사례 목록(N건, 검수 완료·공개 상태만)이 표시된다.
3. 사례를 클릭해 3~5줄 요약, 지적유형, 조치수준을 확인한다.
4. 원문 PDF 속성에서 파일을 다운로드한다.

**보조 흐름 — 신규 사례 등록 및 검수**

1. 담당자가 금융감독원 공개 감리지적사례집에서 사례를 선별해 새 페이지를 생성하고 원문 PDF를 첨부한다.
2. AI가 원문을 바탕으로 요약·지적유형·관련 계정과목(Relation) 초안을 작성한다 (`검수상태 = 초안`).
3. 회계사(담당자)가 초안을 검토·수정하고 `검수상태 = 공개`로 전환한다.
4. 공개 전환 즉시 관련 계정과목 페이지에서 해당 사례가 노출된다.

## 6. Notion 데이터 모델

계정과목 ↔ 감리지적사례는 **N:M 관계**다. 사례 1건이 여러 계정과목에 걸칠 수 있고, 계정과목 1개에 여러 사례가 연결될 수 있다.

### 6.1 데이터베이스 구성 (4개)

```
[회사]  ──Relation──  [계정과목]  ──Relation(N:M)──  [감리지적사례]  ──Relation──  [담당자]
```

### 6.2 회사 DB

| 속성명   | 타입     | 필수 | 예시              |
| -------- | -------- | ---- | ----------------- |
| 회사명   | Title    | ✅   | `[예시] 가나전자` |
| 산업분류 | Select   |      | 제조업            |
| 담당팀원 | Relation | ✅   | → 담당자 DB       |
| 계정과목 | Relation |      | → 계정과목 DB     |

### 6.3 계정과목 DB

| 속성명       | 타입     | 필수 | 예시                                                  |
| ------------ | -------- | ---- | ----------------------------------------------------- |
| 계정과목명   | Title    | ✅   | 매출채권                                              |
| 분류체계     | Select   | ✅   | `{{계정과목_체계}}` (기본: K-IFRS 재무제표 표시 기준) |
| 상위분류     | Select   |      | 자산 / 부채 / 자본 / 손익                             |
| 관련 사례    | Relation | ✅   | → 감리지적사례 DB                                     |
| 관련 사례 수 | Rollup   |      | 관련 사례 개수(Count)                                 |

### 6.4 감리지적사례 DB (핵심)

| 속성명        | 타입         | 필수 | 예시                                         |
| ------------- | ------------ | ---- | -------------------------------------------- |
| 사례명        | Title        | ✅   | `[예시] 수익인식 시기 조기계상 지적`         |
| 요약          | Text (3~5줄) | ✅   | AI 초안 → 회계사 검수 후 확정                |
| 지적유형      | Select       | ✅   | 수익인식 / 자산평가 / 부채인식 / 공시누락 등 |
| 조치수준      | Select       | ✅   | 경고 / 시정요구 / 과징금 / 검찰고발 등       |
| 지적연도      | Number       | ✅   | `[예시] 2023`                                |
| 감독기관      | Select       | ✅   | 금융감독원 / 증권선물위원회                  |
| 관련 계정과목 | Relation     | ✅   | → 계정과목 DB (N:M)                          |
| 원문 PDF      | File & Media | ✅   | 첨부 파일                                    |
| 검수상태      | Select       | ✅   | 초안 / 검수중 / 공개 (기본값: 초안)          |
| 등록 담당자   | Relation     | ✅   | → 담당자 DB                                  |
| 등록일        | Created time |      | 자동 생성                                    |

> 공개 뷰·Rollup 필터는 항상 `검수상태 = 공개`를 조건으로 걸어 미검수 사례가 노출되지 않도록 한다.

### 6.5 담당자 DB

| 속성명    | 타입     | 필수 | 예시                               |
| --------- | -------- | ---- | ---------------------------------- |
| 이름      | Title    | ✅   | `[예시] 김민준`                    |
| 역할      | Select   | ✅   | 스태프/인차지/파트너/콘텐츠 관리자 |
| 배정 회사 | Relation |      | → 회사 DB                          |

## 7. 뷰(View) 설계

| 뷰 이름              | 소속 DB      | 구성                                                                   |
| -------------------- | ------------ | ---------------------------------------------------------------------- |
| 계정과목별 그룹 보기 | 감리지적사례 | Group by `관련 계정과목`, Filter `검수상태 = 공개`                     |
| 회사별 필터 보기     | 계정과목     | 회사 페이지에서 Linked Database로 임베드, 회사 Relation 필터           |
| 검수 대기 보드       | 감리지적사례 | Board view, Group by `검수상태` (초안/검수중/공개 칸반)                |
| 사례 페이지 템플릿   | 감리지적사례 | 요약 · 지적유형 · 조치수준 · 원문 PDF 순서로 고정 배치된 페이지 템플릿 |

| 공개 전환                  |           —           |      R/A       |   —    |   —    |
| 오류 신고 및 수정 요청     |           I           |       C        |   R    |   A    |

R=Responsible, A=Accountable, C=Consulted, I=Informed

## 11. MVP 제외 범위 (Out of Scope)

- 금융감독원·DART 등 외부 사이트에서의 **자동 크롤링/수집** — 이번 MVP는 수동 등록만
- **별도 웹/모바일 앱 개발** — 순수 Notion 워크스페이스로만 구현
- Notion 기본 검색을 넘어서는 **고도화된 전문(全文) 검색/필터링 엔진**
- 감사팀 외부로의 **공유·게스트 초대 및 알림 자동화**
- 사례-계정과목 매핑의 **AI 자동 확정**(검수 없는 자동 공개) — 항상 사람 검수 필요
- 다국어 지원, 사례 통계·대시보드 고도화

> 위 항목은 이번 MVP 완료 후 별도 검토 대상으로 "향후 고려"에만 해당하며, 채택 여부는 미결정이다.
