# 감리지적사례 원문 PDF 디렉터리

`docs/PRD.md` 6.4절 "감리지적사례 DB"에 적재할 원본 PDF와, 그 적재 상태를 추적하는 인덱스를 보관하는 디렉터리입니다.

## 구성

```
data/audit-cases/
├── README.md         ← 이 파일 (커밋됨)
├── index.json         ← Notion 적재 상태 인덱스 (커밋됨)
├── raw/               ← 원문 PDF (커밋되지 않음 — .gitignore 처리)
└── knowledge/          ← PDF에서 추출한 가공 지식 (커밋됨)
    ├── sourcebook-index.md   ← 사례집 구조·목차·페이지 변환 공식
    ├── cases/                ← 사례 1건당 카드 1개
    └── taxonomy.md           ← 관찰된 지적유형·계정과목 분류 체계
```

`raw/`의 원문 PDF 1개가 사례 여러 건을 묶은 **사례집**일 수 있다 — 예: `FSS_회계심사감리 주요지적사례(2020-2023년).pdf`는 151쪽 안에 62건이 들어있다. 이 PDF는 **ToUnicode 정보가 없어 텍스트 추출이 불가능**하고, `audit-case-ingestor` 에이전트가 페이지를 이미지로 렌더링해 시각적으로 읽는 방식으로만 처리한다 (`knowledge/sourcebook-index.md`에 상세 기록).

## `raw/`가 git에 커밋되지 않는 이유

`docs/PRD.md` 13번(리스크 및 대응)의 "원문은 공개된 감리지적사례집 출처를 명시하고 재배포 범위를 사내로 한정" 정책에 따라, 원문 PDF는 로컬(또는 사내 공유 스토리지)에만 두고 이 git 저장소에는 커밋하지 않습니다. `.gitignore`의 `/data/audit-cases/raw/` 규칙이 이를 강제합니다.

## 파일명 규칙

```
{지적연도}-{일련번호}-{핵심키워드}.pdf
```

예: `2023-001-수익인식.pdf`, `2023-002-재고자산평가.pdf`

- `지적연도`: 4자리
- `일련번호`: 같은 연도 내 3자리, 001부터
- `핵심키워드`: 지적유형을 짧게 요약 (공백 없이)

`audit-case-ingestor` 서브에이전트가 파일명에서 연도를 1차 참고값으로 사용하지만, 최종 `지적연도` 값은 항상 PDF 본문 내용을 근거로 확정합니다.

## `index.json`

`raw/`의 PDF 62건 중 어디까지 Notion에 적재했는지 추적하는 유일한 진실 원천입니다. `audit-case-ingestor` 서브에이전트가 실행 때마다 처리한 건을 append하며, 재실행 시 이미 등록된 파일은 건너뜁니다(멱등성). 레코드 스키마는 `.claude/agents/docs/audit-case-ingestor.md`를 참고하세요.

## 사용 방법

1. 이 디렉터리의 `raw/`에 PDF 62건을 넣습니다 (파일명 규칙 준수 권장, 필수는 아님).
2. `audit-case-ingestor` 서브에이전트를 호출해 PDF를 읽고 Notion `감리지적사례 DB`에 `검수상태 = 초안`으로 적재합니다.
3. 회계사가 Notion에서 초안을 검수하고 `검수상태 = 공개`로 전환합니다 (서브에이전트는 이 전환을 수행하지 않습니다).
